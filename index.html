How it works

What is this addon?

Bonnie's Source Engine brings Source engine (Hammer) style map making to Minecraft Bedrock: tool blocks such as triggers, clips and area portals, logic blocks such as relays, timers and counters, and an input/output system to connect them. This encyclopedia covers every one of those engine blocks; each block page shows the same help as the block's in-game Help tab, plus its settings, outputs and inputs.

Placing and editing blocks

  • Engine blocks are only visible while you hold that block's item. Everyone else sees nothing, but the block keeps working. To always show them, run /brr engine_blocks_always_visible true.
  • Use (right-click) a block in Creative mode to open its form. Sneak while using it to place a block against it instead.
  • Brushes (the tool blocks: trigger, area portal, clips, invisible, blocklight) merge with touching blocks of the same type into one entity with one set of settings, so you can build a whole volume and configure it once.
  • Point entities (logic, info, filter and game blocks) are one block each.
  • Give a block a Name if other blocks should target it. Names are not case-sensitive, several blocks may share one, and a target ending in * matches every name starting with that text.

The block form

Every block form has these tabs. The Settings tab of each block page in this encyclopedia lists the ones specific to that block.

Class
The block's main settings. Name and Start disabled are on every block.
Block tabs
Some blocks have extra tabs, such as Cases on logic_case, Auto on logic_auto or Score on math_counter.
Output
Adds a connection from this block to another one (see below).
Saved
Lists and deletes this block's outputs, and the entries of list tabs like Cases.
Input
Shows which other blocks send inputs to this one.
Help
Examples, Usage and Info pages, the same text as this encyclopedia. The trigger also has a Conditions page, which is the Condition Reference here.

Connecting blocks (outputs)

Blocks talk to each other the way Source entities do: when something happens, a block fires an output (like OnStartTouch or OnTimer), and every connection on that output sends an input (like Enable or Trigger) to a target block.

Examples are written as My output > Target entity > Target input, so OnStartTouch > door_relay > Trigger means "when a player enters, send Trigger to the blocks named door_relay".

Inputs every block accepts

Each block page lists the extra inputs that block understands.

Commands

Most commands need operator permissions, and the ones marked with * need cheats on. The brr: prefix can usually be left out, e.g. /status.

/brr <setting> <true|false>
Changes a setting: engine_blocks_always_visible, tool_blocks_enabled or dynamic_lights.
/brr:status
Shows every setting and how many engine blocks are placed.
/brr:fire * <target> <input> [parameter] [delay]
Sends an input to named blocks, like Source's ent_fire. Delay is in seconds. Of the special targets only !activator (you) and !player work here.
/brr:tool_block_edit * <name> <setting> <value>
Changes one setting on every block with that name.
/brr:find [name]
Without a name, counts placed blocks per type. With a name, lists the matching blocks and where they are (* matches the start of names).
/brr:goto * <name> [index]
Teleports you to a named block; index picks one when several share the name.
/brr:block_fill * <block> <from> <to> [name] [start_disabled] [setting] [value]
Fills an area with an engine block and sets it up in one go. Brush types become one brush (up to 32768 blocks); other types become one block each (up to 256). Block names are the short ids shown on each block page, such as tool_trigger or logic_relay.
/brr:version
Shows the addon version.
